## 1. Объект тестирования

LibraryApp — учебное консольное приложение на C# (.NET 8), реализующее простейшую бизнес-логику
учёта книг в библиотеке. Приложение не использует базу данных: каталог хранится в памяти процесса.

Состав приложения:

- **Book** — модель книги: `Id` (целое), `Title` (строка), `Author` (строка),
  `IsAvailable` (логическое, по умолчанию `true` — книга доступна для выдачи).
- **Library** — каталог книг и операции над ним:
  - `AddBook(Book book)` — добавление книги в каталог;
  - `FindBook(int id)` — поиск книги по идентификатору (возвращает `null`, если книги нет);
  - `BorrowBook(int id)` — выдача книги (доступную книгу помечает как выданную);
  - `ReturnBook(int id)` — возврат книги (помечает книгу как доступную);
  - `PrintCatalog()` — вывод каталога в консоль.
- **Program** — точка входа: создаёт каталог из трёх книг и последовательно выполняет
  шесть сценариев выдачи и возврата, демонстрирующих штатные и ошибочные ситуации.

Назначение приложения — демонстрация полного цикла контроля качества программного модуля:
реализация предметной области, отладка, инспекция кода и документирование результатов.

## 2. Методика тестирования

Применялись три взаимодополняющих метода.

### 2.1. Ручное сценарное тестирование

Приложение запускалось из консоли (`dotnet run`) и в Visual Studio (F5). Проверялись
основные и негативные сценарии: выдача существующей книги, повторная выдача уже выданной
книги, возврат книги, которую не выдавали, обращение к несуществующему идентификатору,
повторный возврат. Для каждого сценария фиксировались ожидаемый и фактический результаты
и код возврата процесса.

### 2.2. Отладка в Visual Studio

В методах `BorrowBook`, `ReturnBook`, `FindBook` устанавливались точки останова
(breakpoints). Отладка выполнялась пошагово (F10 — шаг с обходом, F11 — шаг с заходом
внутрь), значения переменных контролировались в окнах **Локальные (Locals)** и
**Контрольные значения (Watch)**; стек вызовов анализировался в окне **Стек вызовов**.
Для наглядности в Watch добавлялись выражения `book`, `book.IsAvailable`, `_books.Count`.
Дополнительно проверялась реакция отладчика на необработанное исключение
(`System.NullReferenceException`).

### 2.3. Статический анализ кода

В проекте включены анализаторы .NET и проверка стиля:

- `<Nullable>enable</Nullable>` — анализ nullable-контекста (предупреждения CS8618, CS8603);
- `<GenerateDocumentationFile>true</GenerateDocumentationFile>` — проверка XML-документации
  публичных членов (CS1591);
- `<AnalysisLevel>latest-recommended</AnalysisLevel>` и `<AnalysisMode>All</AnalysisMode>` —
  анализаторы качества кода;
- `<EnforceCodeStyleInBuild>true</EnforceCodeStyleInBuild>` — проверка правил стиля при сборке;
- `.editorconfig` — правила именования (приватные поля `_camelCase`), подавление правил
  CA1303 (локализация строк не требуется в консольном приложении) и CA1515 (публичные типы
  оставлены намеренно) с обоснованием.

Результаты сборки анализировались в окне **Список ошибок (Error List)**. Дополнительно код
проверялся вручную на соответствие соглашениям именования (PascalCase — типы и методы,
camelCase — параметры и локальные переменные), на наличие XML-документации, на длину методов
и единственность решаемой задачи, на обработку исключений (отсутствие пустых `catch`
и перехвата всех исключений подряд).

## 3. Найденные дефекты

Все дефекты выявлены на этапе отладки приложения и исправлены. После исправления сценарии
повторно проверены в отладчике и при обычном запуске.

| ID | Описание | Шаги воспроизведения | Ожидаемый результат | Фактический результат | Статус |
|---|---|---|---|---|---|
| BUG-01 | `NullReferenceException` при выдаче книги, которой нет в каталоге: результат `FindBook` не проверяется на `null` | Запустить приложение; выполнить `BorrowBook(99)` | Сообщение «книга с Id = 99 не найдена», приложение продолжает работу | Необработанное `System.NullReferenceException` в `Library.BorrowBook`, аварийное завершение процесса | Исправлен |
| BUG-02 | Повторная выдача уже выданной книги разрешается: состояние `IsAvailable` не проверяется | Выдать книгу Id = 1, затем повторно вызвать `BorrowBook(1)` | Отказ с сообщением «книга уже выдана читателю» | Книга повторно «выдана», выводится сообщение об успехе | Исправлен |
| BUG-03 | Возврат книги, которая не была выдана, проходит успешно: `ReturnBook` не проверяет текущее состояние | Вызвать `ReturnBook(2)` для доступной книги, которую не выдавали | Сообщение «книга не была выдана, возврат невозможен» | Книга помечена как возвращённая, выводится сообщение об успехе | Исправлен |
| BUG-04 | Нарушен nullable-контракт: `FindBook` объявлен как возвращающий `Book`, но может вернуть `null` (предупреждение CS8603); любой вызывающий код подвержен NRE | Собрать проект; проанализировать предупреждение CS8603 | Метод возвращает `Book?`, вызывающий код обязан обработать отсутствие книги | Возможен `null` в переменной типа `Book` | Исправлен |
| BUG-05 | `AddBook` не проверяет аргумент: `null` приводит к исключению при добавлении, а дубликат `Id` делает поиск неоднозначным | Вызвать `AddBook(null)`; добавить две книги с одинаковым `Id` | `ArgumentNullException` для `null`, `InvalidOperationException` для дубликата `Id` | Исключение в неожиданном месте / дубликат попадает в каталог | Исправлен |

## 4. Результаты инспекции кода

Инспекция выполнялась по исходному коду модулей `Book.cs`, `Library.cs`, `Program.cs`
с использованием окна «Список ошибок» и ручного просмотра. До исправлений сборка давала
**15 предупреждений** (0 ошибок); после — **0 предупреждений и 0 ошибок**.

| ID | Замечание | Обоснование | Исправление |
|---|---|---|---|
| INS-01 | Отсутствует XML-документация публичных типов и членов (12 × CS1591) | Публичный API модуля должен быть документирован | Добавлены `<summary>`, `<param>`, `<returns>`, `<exception>` для всех публичных типов и членов |
| INS-02 | Свойства `Title` и `Author` не инициализированы (2 × CS8618) | Nullable-контекст включён, неинициализированные non-nullable свойства недопустимы | Свойства объявлены как `required ... { get; init; }` |
| INS-03 | `FindBook` возвращает `Book`, хотя может вернуть `null` (CS8603) | Нарушение nullable-контракта — источник NRE (см. BUG-01) | Возвращаемый тип изменён на `Book?`, вызывающий код проверяет результат |
| INS-04 | Публичный сеттер `IsAvailable` позволяет менять состояние книги в обход `Library` | Инкапсуляция: состояние должно меняться только операциями выдачи/возврата | Сеттер ограничен: `internal set`; класс `Book` сделан `sealed` |
| INS-05 | Приватное поле `books` не соответствует принятому стилю именования | Единый стиль повышает читаемость; правило зафиксировано в `.editorconfig` | Поле переименовано в `_books`, добавлено правило именования `_camelCase` |
| INS-06 | `AddBook` не валидирует входной параметр и дубликаты `Id` | Отсутствие проверок — потенциальный источник ошибок | Добавлены `ArgumentNullException.ThrowIfNull` и проверка дубликата с `InvalidOperationException` |
| INS-07 | В `BorrowBook`/`ReturnBook` смешаны проверки и изменение состояния, в `PrintCatalog` не обработан пустой каталог | Метод должен решать одну задачу и корректно обрабатывать граничные случаи | Проверки выделены в начало методов с ранним возвратом; `PrintCatalog` выводит сообщение для пустого каталога; в `Program` выделен помощник `RunScenario` |
| INS-08 | Дублирование строковых сообщений и «магические» строки | Повторяющиеся литералы усложняют сопровождение | Сообщения вынесены в интерполированные строки внутри одного модуля, дублирование устранено; для консольного приложения локализация признана избыточной (CA1303 подавлен с комментарием) |
| INS-09 | Отсутствует контроль стиля и уровня анализа | Без анализаторов дефекты стиля и nullable-контрактов остаются незамеченными | Включены `AnalysisLevel`, `AnalysisMode`, `EnforceCodeStyleInBuild`, добавлен `.editorconfig` |

Дополнительно проверено: пустых блоков `catch` нет, перехвата всех исключений подряд нет
(исключения возникают только в `AddBook` при нарушении контракта), имена типов и методов
соответствуют PascalCase, параметры и локальные переменные — camelCase, длина методов
не превышает 15–20 строк.

Скриншоты окон «Список ошибок» до и после исправлений — в каталоге
[`docs/screenshots`](docs/screenshots).

## 5. Итоги

- Разработано консольное приложение LibraryApp (.NET 8) с разделением предметной модели
  (`Book`) и бизнес-логики (`Library`).
- На этапе отладки найдено и исправлено **5 дефектов**, в том числе три логические ошибки,
  приводившие к неверным сообщениям и аварийному завершению (`NullReferenceException`).
- После исправлений все шесть демонстрационных сценариев отрабатывают корректно,
  процесс завершается с кодом 0; необработанных исключений нет.
- Статический анализ: сборка проходит без ошибок и предупреждений (0/0), публичный API
  документирован, nullable-контракты соблюдены, стиль именования зафиксирован в `.editorconfig`.
- Покрытие тестами: автоматизированные юнит-тесты в рамках работы не использовались;
  выполнено ручное сценарное тестирование (7 проверок) с пошаговой отладкой, что покрывает
  все ключевые ветви методов `BorrowBook` и `ReturnBook` и граничные случаи `FindBook`.
